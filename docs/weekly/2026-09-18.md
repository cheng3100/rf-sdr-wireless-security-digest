## 一、软件为主的 SDR / wireless hack 动向与新项目

### AetherSDR v26.9.3：从 radio client 继续向可观测、可自动化 workstation 演进

AetherSDR 在 2026-09-13 发布 v26.9.3。相比上期 v26.9.2 增加 RTL-SDR/ANAN-G2 backend，这一轮重点转向运行时可观测性、数字模式和 headless engine：新增 Runtime Monitor Overview，可观察 CPU、最大线程占用、RSS memory、GUI tick lag；APRS 增加 WIDE1-1 fill-in digipeater；aetherd 的本地控制继续按 capability/显式授权逐步开放；音频处理则开始显式区分 producer PCM rate domain。

**具体 Release：** https://github.com/aethersdr/AetherSDR/releases/tag/v26.9.3

值得关注的工程链路是：radio backend → IQ/audio stream → DSP/digital modes → runtime telemetry → headless control/automation。它体现成熟 SDR workstation 的瓶颈逐渐从“能否解调”转向多 backend、多 consumer、运行时性能与安全控制边界。

**本期最值得试用的软件项目：AetherSDR v26.9.3。** 如果读代码，建议重点看 Runtime Monitor 的线程/GUI lag 统计，以及 aetherd 为什么默认 observe-only、控制能力为什么按 capability 和显式 grant 开放。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### gr-autopilot：让 AI 生成 GNU Radio flowgraph 后真正闭环到 SDR HIL

GRCon26 的 `gr-autopilot: An Agentic Framework for Closed-Loop Flowgraph Synthesis with Hardware-in-the-Loop Feedback` 把 LLM/MCP 生成 flowgraph 从 open-loop 推进到真实 RF hardware feedback。agent 生成 Tx/Rx flowgraph，部署到 USRP/ADALM-Pluto，通过受控 RF path 做自动 HIL 测试，再根据实际观测迭代设计。

**具体 GRCon contribution：** https://events.gnuradio.org/event/28/contributions/867/

链路可概括为：自然语言目标 → GNU Radio block/flowgraph synthesis → USRP/Pluto 部署 → OTA/受控 RF path → BER/EVM/频谱等观测 → agent 修正参数/结构。

它的长期价值不只是“AI 写 GNU Radio”，而是把 RF 系统开发中最难自动化的一步——真实硬件、时钟、增益、CFO、噪声和 channel impairment——放回优化闭环。对于自动回归测试、HIL 和 SDR CI，这个方向比单纯生成 `.grc` 文件更有工程意义。

## 三、RF / Wireless 最新动态与新闻

### CVE-2026-16769：Silicon Labs Wi-Fi 模块接受未加密 pause-encryption request 导致 DoS

2026-09-08 公开的 CVE-2026-16769 影响 Silicon Labs RS9116W / SiWx917（WiseConnect 2.x）。问题是设备会处理本应受保护的未加密 `pause encryption request`，无线范围内的未认证攻击者可触发 availability failure。该问题被标记为相关研究中的 B-E10。

**CVE 技术摘要：** https://symaro.com/cve/cve-2026-16769.html

**相关论文：Proteus / State Machine Mutation-based Testing Framework for Wireless Communication Protocols：** https://arxiv.org/abs/2409.02905

这个 CVE 最值得关注的是其来源链路。Proteus 并非传统 bit-level fuzzing，而是围绕 protocol state machine 和安全 property 生成“多数步骤合法、少量步骤有控制偏离”的 message sequence，在 LTE/BLE 设备上寻找逻辑漏洞。论文报告在 23 个消费设备上发现 25 个 unique issues、112 个实例。

因此这里的攻击面不是典型 `length → memcpy → overflow`，而是：合法状态 → 不合预期的保护级别/消息顺序 → implementation 接受本应拒绝的 transition → DoS/安全属性破坏。

**本期最值得关注的 RF / Wireless 动态：CVE-2026-16769 与 Proteus 的“state-machine fuzzing → 多年后 CVE 落地”链路。** 它提示无线协议 fuzzing 不能只做 packet mutation，还应把状态转换、消息保护级别和 cross-state property 纳入模型。

## 四、会议 / 活动高质量研究

### USENIX Security ’26：PrivacyShield — Relaying BLE Beacons to Counter Unsolicited Tracking

**具体 Session：** https://www.usenix.org/conference/usenixsecurity26/presentation/hofhammer

**论文：** https://francozappa.github.io/publication/2026/pshield/paper.pdf

**可复现实验代码 / artifact：** https://github.com/HexHive/privacyshield

PrivacyShield 研究 Apple Find My、Google Find My Device 等 offline finding network 的反跟踪边界。核心观察是：finding tag 周期性广播 BLE beacon，附近联网设备负责把位置上传；而这些 BLE beacon 本身缺少足够的发送者/位置真实性认证，因此可以被捕获并在另一个地理位置 relay。

作者没有只把 relay 当攻击，而是反过来把它用于 anti-stalking：客户端收集目标 BLE beacon → server 分发 advertisement → 远端 ESP32 relay 重放 → 第三方手机在错误地点上报 beacon → finding network 中的目标位置被混淆。

研究 artifact 很完整：Python Flask relay server、定制 AirGuard Android app、ESP32 relay firmware、基于 Sniffle 的 BLE 实验代码，以及读取/可视化 Find My location report 的脚本。也就是说它覆盖 BLE RF → beacon capture → network relay → RF retransmission → crowdsourced geolocation backend → privacy effect 的完整链路。

长期价值在于它揭示一个很通用的系统问题：**应用层位置数据库即使有加密，也无法自动证明“这个 RF beacon 真的是在这个地点发射的”。** 这与 ADS-B、AIS、Remote ID 等“协议声明 vs 物理位置证据”问题具有共通性。

**本期最值得精读的会议 / 活动研究：PrivacyShield。**

## 五、本期最值得精读的 RF 原理文章

### Wireless Pi：Design of a Low-SNR Receiver

**原文：** https://wirelesspi.com/design-of-a-low-snr-receiver/

这篇文章很适合在已经分别学习 IQ、filter、pulse shaping、同步和 TDOA 后，用一个完整 OFDM receiver 把多个 impairment 串起来。它从带 multipath、CFO 和 AWGN 的时域接收模型出发，依次讨论 coarse timing、coarse CFO、fine timing/frequency、SNR estimation、FFT、channel estimation/equalization，以及低 SNR 下 residual phase tracking 与 iterative decoding。

关键模型可以概括为：`y[n] = CFO × (h[n] * x[n]) + w[n]`。进入 OFDM frequency domain 后，理想情况是 `Y[k] = H[k]X[k] + W[k]`；但 residual CFO 会额外产生 constellation rotation 和 ICI。因此同步不是一个独立前处理步骤，而是会直接改变后面的 channel estimation、equalizer 和 decoder 是否能收敛。

文章尤其值得注意的是“低 SNR 改变 receiver 设计优先级”：高 SNR 时某些 residual phase error 可以被 channel estimator 顺手吸收，低 SNR 时估计本身变差，必须利用训练序列、非数据辅助 phase estimator 或迭代结构保持稳定。

建议实验：用 GNU Radio/Python 构造 QPSK/OFDM，固定 multipath 后逐步降低 SNR，并分别加入 CFO；记录 coarse sync metric、FFT 后 constellation、channel estimate、EVM/BER，观察哪个环节先失稳。再比较“只做一次 CFO correction”和“持续 residual phase tracking”的差异。

**本期最值得精读的 RF 原理文章：Wireless Pi — Design of a Low-SNR Receiver。**
