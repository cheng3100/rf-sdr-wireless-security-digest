## 一、软件为主的 SDR / wireless hack 动向与新项目

### [SDRangel 7.27.1 / MeshCore 插件](https://github.com/f4exb/sdrangel/releases)
SDRangel 7.27.0/7.27.1 在 2026 年 7 月加入并修复 MeshCore Rx/Tx 插件。MeshCore 是基于 LoRa 的离网 mesh 系统；这类插件值得关注的不是单一协议本身，而是 SDRangel 如何把调制、解调、网络协议和 GUI/设备抽象组合进统一插件体系。

**适用：** LoRa / MeshCore、通用 SDR 收发、协议观察与离网 mesh 实验。

### [SatDump 2.0 Alpha](https://www.satdump.org/tags/release/)
SatDump 2.0 Alpha 继续把 SDR 输入、实时/离线 DSP、同步、FEC、framing、协议解析和图像/遥测恢复整合在同一 pipeline 中。与单独搭建 GNU Radio flowgraph 相比，它更适合作为“从 IQ 到最终业务数据”的完整软件架构样本。

**适用：** 卫星信号接收、VHF/UHF/L/S 波段实践、IQ 数据处理、协议链路学习。

### [Universal Radio Hacker v2.10.0](https://github.com/jopohl/urh/releases)
URH 的经典仓库已于 2026 年 3 月归档，但最终主版本仍值得作为协议逆向方法论参考。v2.10.0 包括 PyQt6 迁移、Cython 兼容、USRP stream buffer 修复等维护性改动。

**适用：** OOK/FSK/GFSK、Sub-GHz 专有协议、多帧比较、编码和 CRC 分析。后续不再把它视作活跃项目动态源，而作为成熟工具基线。

### 本期最值得试用的软件项目

**SDRangel 的 MeshCore Rx/Tx 插件。** 它把 LoRa-based mesh 的真实协议处理放进一个完整 SDR 工作台中，适合从“能收 IQ”进一步观察协议插件如何与实时收发框架结合。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### [PortaPack Mayhem Nightly 2026-07-26](https://github.com/portapack-mayhem/mayhem-firmware/releases)
Mayhem 7 月 nightly 中出现了 TETRA RX、VOR Navigation、EPIRB TX SGB 等一系列无线应用相关变化，最新公开 nightly 为 2026-07-26。它持续体现 HackRF + PortaPack 这种受限嵌入式 RF 平台如何在 UI、DSP、存储和协议应用之间做资源取舍。

**适用：** HackRF/PortaPack、航空导航、mission-critical radio、便携式频谱/协议观察。

### [Maia SDR](https://maia-sdr.org/)
Maia SDR 继续是“RFIC + FPGA + Linux + Web UI”架构的代表项目：AD936x 负责 RF 收发，FPGA 承担高带宽频谱/DSP 数据面，ARM/Linux 运行设备服务并导出 SigMF 数据。

**适用：** ADALM-Pluto / Pluto+、FPGA SDR、远程频谱监测、高采样率 IQ 采集。

### 本期最值得关注的软硬件一体项目

**PortaPack Mayhem。** 本期重点不是硬件规格变化，而是 TETRA、VOR、EPIRB 等应用不断进入设备端，能直接观察“通用 SDR 硬件”如何逐渐形成面向不同无线场景的便携应用平台。

## 四、本期最值得精读的 RF 原理文章

### [PySDR：Synchronization](https://pysdr.org/content/sync.html)
本期从长期高价值源 PySDR 中选择 **Synchronization** 作为精读主题。该章节把数字接收机中的时间与频率同步放在同一接收链路里，覆盖 symbol timing、coarse frequency synchronization、fine frequency synchronization 和 Costas Loop。

它最值得建立的工程模型是：

1. Tx/Rx 本振不可能完全一致，因此会产生 carrier frequency offset；
2. 接收采样点通常不会天然落在最佳 symbol instant，需要 timing recovery；
3. coarse frequency estimation 先把大频偏压到可跟踪范围；
4. fine frequency/phase loop 再持续跟踪残余误差；
5. 很多 fine synchronization 方法依赖 timing 已经基本收敛，因此多个同步模块存在顺序和耦合关系。

PySDR 还给出 Pluto 在 2.4 GHz、25 ppm 条件下可能对应约 ±60 kHz 频偏的例子，直观说明“ppm 很小”并不代表复基带中的 CFO 可以忽略。

**适用：** BPSK/QPSK 等数字调制、Pluto/HackRF/RTL-SDR IQ 数据、协议解调前端、Costas loop 和 Mueller & Muller timing recovery 学习。

**建议实践：** 对一段自有或公开 IQ 数据人为加入已知 CFO 与 sampling offset，依次观察粗频偏估计、timing recovery 和 Costas loop 前后的星座/频谱变化。

### 本期最值得精读的 RF 原理文章

**PySDR 的 Synchronization。** 相比只解释某一个 loop，它更适合作为接收机同步链路的总入口，并能和此前已经收录的 IQ Sampling、Link Budgets 形成连续学习路径。
