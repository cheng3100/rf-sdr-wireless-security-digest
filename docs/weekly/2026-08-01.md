## 一、软件为主的开源项目

### 1. SDRangel 7.27.x

SDRangel 在 2026 年 7 月发布 7.27.0 与 7.27.1。它仍是活跃度较高的综合 SDR 客户端之一，覆盖收发、频谱与瀑布图、信道插件、网络控制和多类 SDR 硬件后端。

**值得关注的原因：** 它更接近一个可扩展 SDR 工作台，而不只是桌面收音机。适合研究设备抽象、实时 IQ pipeline、插件化解调器和远程控制接口。

**建议试用：** 使用同一段离线 IQ，比较 SDRangel、SDR++ 和 GNU Radio 在录制、重采样、滤波与解调流程上的差异。

来源：[SDRangel CHANGELOG](https://github.com/f4exb/sdrangel/blob/master/CHANGELOG)

### 2. FISSURE

FISSURE 是面向 RF 与协议逆向的综合框架，包含信号检测、IQ 操作、模式识别、模糊测试、packet crafting、CRC 计算、数据集构建和多种第三方工具集成。当前主线已经转向 Python 3，并支持 GNU Radio 3.8/3.10。

**适用场景：** 当研究从“查看一个信号”扩展到“检测—分类—协议分析—测试—数据归档”的完整流程时，它比单独使用 URH 或 GNU Radio 更接近工作流平台。

**是否值得立即安装：** 中等。功能强，但环境较重。建议先在独立 Ubuntu 环境或容器中评估。

来源：[FISSURE](https://github.com/ainfosec/FISSURE)

### 3. URH / URH-NG 路线

经典 URH 仍然是 OOK、FSK、GFSK 等未知协议逆向的重要工具。后续应持续关注其维护状态以及 URH-NG 等延续项目，尤其是新版 Python/Qt 兼容、自动符号率识别、CRC 搜索和 whitening 支持。

**与你的实践关系：** 适合对遥控器、无线传感器和自有 Sub-GHz 设备做多帧对比、字段划分与编码推断。

### 本期最值得试用的软件项目

**SDRangel 7.27.x。** 安装和上手门槛相对可控，同时能建立通用 SDR 客户端、专用解码器和 GNU Radio 流图之间的工程认知。

## 二、软硬件一体或硬件主导项目

### 1. HackRF 2026.01.3

HackRF 项目在 2026 年 1 月发布 2026.01.3。其仓库同时维护硬件设计、固件与主机软件，是典型的开源 SDR 软硬件一体项目。

**推荐阅读方式：** 分成三层理解：

1. RF 前端、时钟与模拟链路；
2. MCU/CPLD 固件和采样数据通路；
3. libhackrf、USB streaming 与 host 工具。

这对有 Linux 驱动背景的人尤其有价值，因为可以把 SDR 看成一个持续高速传输 IQ 数据的 USB 设备，而不是黑盒射频仪器。

来源：[Great Scott Gadgets HackRF](https://github.com/greatscottgadgets/hackrf)

### 2. RemoteRF

RemoteRF 是 2026 年公开的开源远程 SDR 实验平台，目标是集中管理多台 SDR，并支持远程预约、实验执行和资源共享。

**工程价值：** 它把 SDR 从单机工具提升为共享基础设施，涉及设备调度、多用户隔离、实验生命周期和远程硬件访问控制。

来源：[RemoteRF](https://arxiv.org/abs/2606.22161)

### 3. 可部署 RF 采集节点

2026 年的一项开源研究使用 HackRF One、Raspberry Pi 5、GNSS 和高速 SSD 构建便携 RF 采集系统，并使用 SigMF 保存带时间与位置元数据的 IQ 数据。

**值得关注的部分：** USB streaming、持续写盘、buffer underrun、GNSS 时间标记和 SigMF 元数据。它展示了 SDR 系统的瓶颈往往出现在 USB、内存拷贝和存储，而不只是 RF 芯片。

来源：[Field-Deployable RF Capture System](https://arxiv.org/abs/2607.01368)

### 本期最值得关注的软硬件一体项目

**HackRF。** 不是因为它最新，而是因为它公开了从射频硬件到固件和 host software 的完整边界，最适合系统性阅读。

## 三、无线安全与协议研究

### 1. Pair-Fi：让手机 Wi-Fi 芯片具备 SDR 类能力

Pair-Fi 是 WiSec 2026 最佳论文。研究通过修改手机集成 Wi-Fi 芯片固件，获得精细时序与信号控制能力，并用于具有完整性保护的安全设备配对。

**为什么重要：** 它说明 SDR 类能力不一定来自外置 USRP/HackRF，也可能通过开放商用 Wi-Fi 芯片的固件和 PHY 控制接口获得。非常适合从 firmware、driver 与 PHY 三层关系理解。

来源：[Pair-Fi](https://doi.org/10.1145/3765613.3811679)

### 2. HardaBLE：在软件已被攻破时保护 BLE

HardaBLE 关注传统 BLE 威胁模型之外的问题：当设备软件已被攻破、攻击者能够读取内存时，长期密钥可能被提取，进而用于冒充或解密通信。该工作研究如何强化 BLE，使其在软件 compromise 场景下仍保留更强安全边界。

**值得关注的原因：** 它把无线安全从“空口攻击”扩展到“host 软件、密钥生命周期和无线协议共同失陷”的系统问题。

来源：[HardaBLE](https://www.eurecom.fr/en/publication/8763)

### 3. BlueBrothers：重新设计 Bluetooth 安全协议

BlueBrothers 针对 Bluetooth 配对与会话建立中缺少完整性、前向保密或强认证等问题，提出三个新的安全协议。

**实践意义：** 阅读重点不应是直接复现攻击，而是比较 Bluetooth 现有 handshake 与新协议在认证、密钥更新和降级抵抗方面的差异。

来源：[BlueBrothers](https://doi.org/10.1145/3765613.3816113)

## 四、RF / SDR 原理精读

### 1. 载波频偏与符号定时同步

建议精读 Wireless Pi 的 synchronization 系列。接收机本振误差会造成 IQ 相位持续旋转；符号定时误差会使采样点偏离最佳位置，引入 ISI 和判决错误。

推荐入口：[The Fundamental Problem of Synchronization](https://wirelesspi.com/fundamental-problem-synchronization/)

### 2. 分布式阵列中的载波和采样同步

一篇基于 GNU Radio 与 USRP N210 的实现论文同时处理分布式节点的载波频率和采样定时同步。它适合作为从单接收机同步扩展到多节点相干系统的进阶材料。

来源：[Software Defined Radio Implementation of Carrier and Timing Synchronization for Distributed Arrays](https://arxiv.org/abs/1811.02098)

### 3. The Zen of Bluetooth Security

WiSec 2026 keynote 总结了多年 Bluetooth Classic 与 BLE 安全研究形成的原则，并覆盖 BLUFFS、BLUR、BIAS、KNOB、BLERP、HardaBLE 和 BlueBrothers 等工作。

**阅读价值：** 它比单独追一篇漏洞论文更适合建立 Bluetooth 安全研究的方法论和问题地图。

来源：[The Zen of Bluetooth Security](https://www.eurecom.fr/en/publication/8764)

### 最值得精读的 RF 原理文章

**Wireless Pi 的同步系列。** 这是从“会看频谱”走向“能实现可靠解调器”的关键基础。

## 五、可执行的小实验

### 离线 IQ 频偏注入与补偿

1. 用 RTL-SDR 或 HackRF 录制自有 OOK/FSK 设备的一段 IQ；
2. 在 Python 中乘以复指数，分别注入 100 Hz、1 kHz、5 kHz 频偏；
3. 比较频谱中心、相位随时间变化和 bit 判决结果；
4. 使用已知频偏做反向补偿；
5. 将采样率、中心频率、注入频偏和结果记录到 SigMF 或 Markdown。

该实验不需要发射，能直接建立“频偏—IQ 旋转—滤波器失配—解调错误”之间的联系。
