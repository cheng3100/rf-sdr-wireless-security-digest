# RF / SDR / Wireless Security 技术情报 · 2026-08-01

> 本期是按新分类规则进行的更新测试。安全研究内容仅面向自有设备、实验室环境和明确授权测试。

## 一、软件为主的开源项目

### 1. SDRangel 7.27.x

SDRangel 在 2026 年 7 月继续发布 7.27.0/7.27.1。它不是新项目，但仍是目前最活跃的综合 SDR 客户端之一，覆盖接收、发射、频谱、信道插件、网络控制和多种硬件后端。

**为什么值得关注：** 对比 SDR++ 这类偏桌面接收客户端，SDRangel 更像可扩展的 SDR 工作台。适合研究设备抽象、实时 IQ pipeline、插件化解调器和远程控制接口。

**试用建议：** 用同一段 IQ 或同一只 RTL-SDR，对比 SDRangel、SDR++ 与 GNU Radio 在频谱观察、录制、重采样和解调流程上的差异。

来源：[SDRangel CHANGELOG](https://github.com/f4exb/sdrangel/blob/master/CHANGELOG)

### 2. AIS-catcher 0.68

AIS-catcher 是面向 AIS 的高性能 SDR 接收器，支持 RTL-SDR、Airspy、HackRF、SDRplay 与 SoapySDR，并提供 Web viewer、网络输出和 Python binding。0.68 于 2026 年 4 月发布。

**技术价值：** 它是学习“专用协议接收器”工程结构的好样本：设备输入、滤波、同步、解调、帧解析、网络输出和长期运行被组织成完整产品，而不只是一个 GNU Radio flowgraph。

来源：[AIS-catcher](https://github.com/jvde-github/AIS-catcher)

### 3. 分布式 SDR 信号检测项目 SIGINT

`arall/sigint` 把 RTL-SDR/HackRF 节点、中心调度、SQLite、Web dashboard、Meshtastic 和 ATAK/CoT 串成分布式信号检测系统，面向短脉冲与持续发射源的记录和定位。

**值得研究的部分：** 重点不是具体“侦察”用途，而是多节点采集时间线、检测结果聚合、任务调度和数据可视化。它可作为自建多接收机 RF 监测平台的架构参考。

来源：[arall/sigint](https://github.com/arall/sigint)

### 本期最值得试用的软件项目

**SDRangel 7.27.x。** 原因是安装门槛相对低、硬件覆盖广，并且最适合用来建立“通用 SDR 客户端”与“协议专项解码器”之间的工程认知。

## 二、软硬件一体或硬件主导项目

### 1. HackRF 2026.01.3

HackRF 项目在 2026 年 1 月发布 2026.01.3。仓库同时维护硬件设计、固件和 host software，是典型的开源 SDR 软硬件一体项目。

**本期关注点：** 不把它仅当作现成射频外设，而是按三层阅读：RF/模拟前端与时钟、MCU/CPLD 固件数据通路、libhackrf/host 工具。它非常适合你从 Linux 驱动与设备通信视角研究 USB streaming、buffer 生命周期和固件接口。

来源：[Great Scott Gadgets HackRF](https://github.com/greatscottgadgets/hackrf)

### 2. mcHF 开源 HF SDR 收发机

mcHF 是 3–30 MHz 的完整开源 SDR 收发机，硬件与固件均开放，包含触摸屏、实时 waterfall/spectrum、SSB/AM/FM/CW 和功率放大部分。

**与 HackRF 的区别：** HackRF 更像通用 RF 外设；mcHF 更像完整独立无线电产品。它适合研究从天线、滤波、ADC/DAC、DSP、UI 到功放和电源的系统闭环。

来源：[m0nka/mcHF](https://github.com/m0nka/mcHF)

### 3. Langstone V3

Langstone V3 将 Raspberry Pi 5、触摸屏与 PlutoSDR 或 HackRF 组合成 VHF/UHF/微波段实验型收发机，支持 SSB、CW 和 FM。

**技术意义：** 它展示了“通用计算平台 + 现成 SDR 射频前端 + 专用操作界面”的快速产品化路径，适合观察实时性、音频、GUI 与 SDR 数据流如何组合。

来源：[g4eml/Langstone-V3](https://github.com/g4eml/Langstone-V3)

### 本期最值得关注的软硬件一体项目

**mcHF。** 它比单独的 SDR dongle 更完整，能够帮助理解一个真正收发机中 RF 前端、基带 DSP、控制面、用户界面和功率链路的边界。

## 三、无线安全与协议研究

### 1. Pair-Fi：利用手机 Wi-Fi 芯片的 SDR 类能力增强设备配对

WiSec 2026 的 Pair-Fi 通过修改手机集成 Wi-Fi 芯片固件，获得类似 SDR 的精细时序与信号控制能力，用于传输带完整性保护的配对信息。

**为什么重要：** 它说明“SDR 能力”不一定需要外置 USRP/HackRF；通过固件开放商用 Wi-Fi 芯片的 PHY 控制能力，同样可以构造新的安全原语。这与 Nexmon 类研究路径接近，值得从 firmware/driver/PHY 三层关系理解。

来源：[ACM WiSec 2026 Pair-Fi](https://doi.org/10.1145/3765613.3811679)

### 2. 开源 LoRa PHY 对 SF5/SF6 的逆向扩展

PIMRC 2026 预告工作对既有开源 LoRa PHY 进行扩展，通过逆向支持新增的 SF5 和 SF6，并用仿真、有线衰减和 OTA 实验验证。

**为什么值得跟踪：** 这是“从商用协议行为反推 PHY 参数，再补进开源接收机”的典型案例。后续应重点看同步、chirp 参数、编码链和灵敏度损失如何处理。

来源：[TU Berlin 文献页](https://www.tkn.tu-berlin.de/bib/roesler2026open-source/)

### 3. Zigbee 抗干扰实验

2026 年的一项实验研究使用 HackRF、GNU Radio 与 CatSniffer 分析 Zigbee 网络在射频干扰下的可靠性。其价值主要在防御侧：评估传感器遥测中断、信道占用和系统降级表现。

**实践边界：** 仅应在屏蔽环境或自有 Zigbee 网络中进行，重点放在检测、告警、信道迁移与恢复能力，而不是构造面向他人网络的干扰。

来源：[Procedia Computer Science](https://doi.org/10.1016/j.procs.2026.04.154)

## 四、RF / SDR 原理精读

### 1. 载波频偏与同步

推荐继续精读 Wireless Pi 的同步系列。核心问题是：本振误差会令星座图持续旋转；符号定时误差会使采样点偏离脉冲最佳位置，并引入 ISI。理解这两点后，才能从“看懂瀑布图”走向实现可靠接收机。

推荐入口：[The Fundamental Problem of Synchronization](https://wirelesspi.com/fundamental-problem-synchronization/)

### 2. LoRa 中 CFO/STO 的实际实现

开源 GNU Radio LoRa PHY 工作不仅给出 LoRa 解调流程，也讨论 sampling-time offset 和 carrier-frequency offset 的估计与补偿。建议把它作为同步理论到真实协议实现之间的桥梁。

来源：[An Open-Source LoRa Physical Layer Prototype on GNU Radio](https://arxiv.org/abs/2002.08208)

### 最值得精读的 RF 原理文章

**Wireless Pi 的 synchronization 系列 + 开源 LoRa PHY 的 CFO/STO 实现。** 前者建立通用原理，后者展示这些误差如何进入具体 chirp 接收机。

## 五、可执行的小实验

### 实验：对离线 IQ 人为注入频偏并观察解调退化

1. 使用 RTL-SDR 或 HackRF 录制自有 OOK/FSK 设备的一段 IQ。
2. 在 Python 中乘以复指数，人为加入多个频偏，例如 100 Hz、1 kHz、5 kHz。
3. 比较频谱中心、相位随时间变化和解调输出。
4. 用已知频偏反向补偿，并验证波形与 bit 判决是否恢复。
5. 将结果记录为 SigMF 元数据或实验 Markdown。

这个实验不需要发射，完全基于离线 IQ，能够直接建立“频偏—IQ 旋转—滤波器失配—解调错误”之间的联系。

## 六、本期优先级

1. **动手：** 用 SDRangel 读取或实时接收一段熟悉的 Sub-GHz 信号。
2. **代码阅读：** 选择 AIS-catcher，跟踪从 SDR sample 输入到 AIS frame 输出的完整路径。
3. **系统理解：** 粗读 mcHF 硬件与固件目录，画出 RF、ADC/DAC、DSP、UI 和 PA 的模块边界。
4. **原理：** 完成一次离线 IQ 频偏注入与补偿实验。
