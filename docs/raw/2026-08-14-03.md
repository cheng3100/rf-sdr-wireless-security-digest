## 一、软件为主的 SDR / wireless hack 动向与新项目

### SDRangel：MeshCore Rx/Tx 插件

SDRangel 7.27.x 在 2026 年 7 月加入并修复 MeshCore Rx/Tx 插件。MeshCore 是基于 LoRa 的离网 mesh 系统，这个更新最值得看的不是“又支持了一个协议”，而是一个成熟 SDR 工作台如何把设备输入、实时 channel/DSP、调制解调、协议处理和 GUI/控制组织成插件。

**适用：** LoRa / MeshCore、通用 SDR 收发、协议观察与离网 mesh 实验。

**与实践的关系：** 如果已经熟悉 RTL-SDR/HackRF 的采集和离线 IQ 分析，SDRangel 这类插件非常适合继续观察“实时收发框架如何承载具体无线协议”。

来源：https://github.com/f4exb/sdrangel

### SatDump 2.0 Alpha

SatDump 2.0 Alpha 继续把 SDR 输入、实时/离线 DSP、同步、FEC、framing、协议解析和图像/遥测恢复放在同一 pipeline 中。它比单独的一组 GNU Radio flowgraph 更接近完整 SDR 应用。

**适用：** 卫星信号接收、VHF/UHF/L/S 波段实践、IQ 数据处理和协议链路学习。

**与实践的关系：** 特别适合沿着 source → synchronization/demod → FEC → frame → protocol → payload 的路径阅读代码，把 DSP 和协议软件连接起来。

来源：https://github.com/SatDump/SatDump

### 本期最值得试用的软件项目

**SDRangel 的 MeshCore Rx/Tx 插件。** 它适合从“能采 IQ、能离线解码”进一步进入实时协议插件与完整 SDR 客户端架构。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### PortaPack Mayhem：TETRA / VOR / EPIRB 等设备端能力

PortaPack Mayhem 7 月 nightly 持续增加或修订无线应用。公开 release notes 中可以看到 TETRA RX、Airband VOR receiver/transmitter、EPIRB TX SGB 等变化；最新公开 nightly 为 2026-07-26。

**适用：** HackRF/PortaPack、航空导航、mission-critical radio、应急信标、便携 RF 观察。

**与实践的关系：** 它很适合观察一个资源受限的设备如何同时处理 RF 控制、DSP、协议逻辑、UI 和存储，并把 PC 端工作流逐步下沉到独立设备。

来源：https://github.com/portapack-mayhem/mayhem-firmware/releases

### Maia SDR

Maia SDR 仍然是 FPGA SDR 的高价值系统样本：AD936x 完成 RF 收发，FPGA 负责高带宽频谱/DSP 数据面，Zynq ARM/Linux 运行 Rust 服务，通过 WebAssembly/WebGL 提供浏览器端瀑布图与控制，并支持 SigMF IQ 记录。

**适用：** ADALM-Pluto / Pluto+、FPGA SDR、高采样率频谱、远程监控和 IQ 记录。

**与实践的关系：** 对系统软件视角尤其有价值，因为它清楚展示了“什么应该留在 FPGA 数据面、什么交给 Linux 控制面、什么交给浏览器展示层”。

来源：https://github.com/maia-sdr/maia-sdr

### 本期最值得关注的软硬件一体项目

## 四、会议 / 活动高质量研究

### Black Hat USA 2026：Blind Trust in the 6 GHz Band — Weaponizing Wi-Fi AFC

这是本期最符合“会议研究”新主题定义的案例。研究对象不是一个单独 Wi-Fi 帧漏洞，而是 6 GHz 标准功率 Wi-Fi 依赖的 Automated Frequency Coordination 系统。公开信息显示，研究关注 AFC 对客户端/设备侧信息的信任，以及位置等输入被滥用后可能造成的错误频谱授权和干扰风险。

**完整研究链路可以按下面理解：**

1. 6 GHz 标准功率 Wi-Fi 为避免干扰 incumbent 系统，需要通过 AFC 获取可使用信道/功率；
2. AFC 决策依赖设备位置等外部信息，因此无线系统新增了一个网络化控制面；
3. 如果这些输入的可信边界存在问题，就可能让设备获得不应有的频谱授权；
4. 最终影响不只是 AP 本身，还可能扩展成对 6 GHz 共存系统的 RF 干扰问题。

**值得学习的点：** shared spectrum、6 GHz propagation/AFC、Wi-Fi 系统安全边界、RF 干扰与网络控制面的交叉。

**材料状态：** Black Hat 官方 session 已确认；Black Hat 的通用材料规则是 slides/whitepapers/tools 若由演讲者提供，会挂在 session page。后续应继续检查该 session 的 Presentation Material，而不是用二手新闻替代原始材料。

## 五、本期最值得精读的 RF 原理文章

### PySDR：Synchronization

PySDR 的 Synchronization 章节把数字接收机中的时间和频率同步放到同一条接收链路里，覆盖 symbol timing、coarse frequency synchronization、fine frequency synchronization 和 Costas Loop。

最重要的工程模型是：

1. Tx/Rx 本振不可能完全一致，因此产生 carrier frequency offset；
2. ADC sample 也不会天然落在最佳 symbol instant，需要 timing recovery；
3. coarse frequency estimation 先处理较大的 CFO；
4. fine carrier/phase loop 再跟踪残余频偏和相位；
5. 多个同步模块之间存在顺序和耦合，而不是彼此独立。

PySDR 用 Pluto 在 2.4 GHz、25 ppm 条件下可能产生约 ±60 kHz CFO 的例子说明：ppm 数字看似很小，映射到 GHz 载波后却会成为明显的基带频偏。

**适用：** BPSK/QPSK、Pluto/HackRF/RTL-SDR IQ 数据、Costas loop、Mueller & Muller timing recovery、协议解调前端。

**建议实践：** 给一段 IQ 人为加入已知 CFO 和 sampling offset，依次观察粗频偏校正、timing recovery 和 Costas loop 前后的频谱与星座变化。

来源：https://pysdr.org/content/sync.html

### 本期最值得精读的 RF 原理文章

**PySDR 的 Synchronization。** 它和此前的 IQ Sampling、Link Budgets 一起，可以组成“信号表示 → 链路可达性 → 接收同步”的连续基础学习路线。
