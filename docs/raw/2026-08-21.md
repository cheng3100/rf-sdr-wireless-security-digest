## 一、软件为主的 SDR / wireless hack 动向与新项目

### radiom：面向移动端/浏览器的多协议 SDR 客户端

[radiom](https://github.com/thepacket/radiom) 是 2026 年出现的移动 SDR 应用方向，可以连接 KiwiSDR、OpenWebRX 和 RTL_TCP 服务，并在同一界面里整合大量协议 decoder。仓库当前说明已集成约 88 个协议解码器，并复用了 fldigi、WSJT-X 系、multimon-ng、direwolf、dumphfdl、JS8Call 等现有开源解码生态。

它值得关注的不是“又一个频谱瀑布图”，而是把远端 SDR source、实时音频/IQ、协议 decoder、移动 UI 和网络访问组合成一个软件工作台。对于想把 SDR 做成长期运行、远程访问或移动端工具的人，这类架构比传统桌面单机 SDR 更值得研究。

**适用方向：** KiwiSDR / OpenWebRX / RTL_TCP、业余无线电、多协议监听、移动端 SDR、远程 RF 观察。

### Radio-FM：直接学习原始 I/Q 的 RF foundation model

[Radio-FM](https://arxiv.org/abs/2608.05793) 于 2026 年 8 月提交，目标是对原始 I/Q 数据学习通用 radio representation。它采用针对 I/Q 双通道设计的处理结构，并在 modulation、radar、emitter identification、wireless technology recognition、interference identification 等任务上进行统一预训练和迁移。

这条线值得长期观察，因为它和普通“把频谱图当图片输入模型”不同：模型直接把复基带 I/Q 本身当作基础对象。对 SDR 实践而言，这意味着未来 signal classification、未知信号聚类、干扰识别甚至协议分析前置阶段，可能越来越多地由通用 RF encoder 承担。

### 本期最值得试用的软件项目

**radiom。** 它最适合马上动手：可以把已有 KiwiSDR/OpenWebRX/RTL_TCP 资源接进来，观察一个现代多 decoder SDR 客户端如何组织远程 source、协议处理和移动 UI。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### Pocket SDR v0.19：多通道 GNSS SDR 的软硬件完整链路

[Pocket SDR](https://github.com/tomojitakasu/PocketSDR) v0.19 于 2026-07-24 发布。它是一套开源 GNSS SDR，包括 2/4/8 通道 RF frontend、IF 采集工具和 Python/C/C++ GNSS 接收机软件，支持 GPS、GLONASS、Galileo、QZSS、BeiDou、NavIC 和 SBAS 等多类信号。

v0.19 增加了对 Galileo E1 CBOC 与 E5 AltBOC 等多级副载波 replica 的 int8 correlator 支持，并强化了低 C/N0 acquisition / tracking、pilot extended coherent tracking 和多 stream 输出。项目非常适合从“真实 RF frontend → ADC/IF → correlator → acquisition/tracking → navigation message → PVT”完整学习 SDR 接收机。

**适用频段/硬件：** GNSS L1（约 1525–1610 MHz）以及 L2/L5/L6（约 1160–1290 MHz）；Pocket SDR FE 2/4/8 通道前端。

### HackRF Pro 主线仍在推进新的 radio configuration 能力

[HackRF](https://github.com/greatscottgadgets/hackrf) 的 2026.01.3 仍是当前稳定 release，但主线 pull request 持续推进新的 radio configuration mode、固定点 center-frequency/sample-rate 设置、radio register locking、transceiver temperature 读取等能力。

这些变化说明 HackRF Pro 的软件边界正在从“兼容 HackRF One 的 legacy mode”逐步向更细粒度的射频配置扩展。对软硬件系统学习而言，值得关注 libhackrf API、MCU firmware、gateware 与 RF transceiver 配置之间的接口如何演化。

### 本期最值得关注的软硬件一体项目

**Pocket SDR v0.19。** 它比单一 SDR 板卡更适合系统学习，因为 RF 前端、多通道采样、DSP correlator、tracking 和最终 PVT 都在同一开源项目里。

## 三、RF / Wireless 最新动态与新闻

### Wi-Fi beamforming feedback 被用于无摄像头人体识别

8 月 18 日公开报道的一项研究显示，普通 Wi-Fi 基础设施中的 beamforming feedback 可以被用于人体识别；公开报道描述的实验在 197 名参与者上取得接近 100% 的识别率，而且不要求被识别者自己携带主动设备，只需要环境中存在可产生相关 Wi-Fi 测量的设备。

对 RF / wireless security 来说，这个方向值得关注的不是“Wi-Fi 也能做 sensing”本身，而是 **原本用于链路优化的 PHY/CSI 类反馈正在变成隐私侧信道**。后续 IEEE 802.11bf 等 sensing 标准如何处理反馈暴露、可观测性和隐私边界，会直接影响无线协议设计。

### FCC 推进 unlicensed spectrum 的 satellite Direct-to-Device

FCC 在 2026-08-06/07 推进 `Unleashing Unlicensed Spectrum for Direct-to-Device` NPRM（FCC-26-51，ET Docket 26-169），探索允许部分 Part 15 非授权频段设备与获授权卫星直接通信，并讨论非授权设备在 spacecraft 中的使用。

这件事对 RF 工程的意义是：传统“地面 ISM/unlicensed device”与卫星链路之间的边界正在变模糊。未来做 SDR 频谱观察时，某些频段的信号来源、链路预算、干扰模型和监管假设都可能变化。

### 本期最值得关注的 RF / Wireless 动态

**Wi-Fi beamforming feedback 的隐私侧信道化。** 它直接体现了无线 PHY 原本为了性能暴露的信息，如何被重新解释成 sensing/identity 信息。

## 四、会议 / 活动高质量研究

### BLERP：BLE Re-Pairing Attacks and Defenses

BLERP 是本期最值得完整归档的一条研究。它既在 Black Hat Asia 2026 以 `Exploiting BLE re-pairing with the BLERP attacks` 形式演讲，也有 NDSS 2026 的完整 paper、slides 和 video，因此材料链完整。

**具体研究页：** [NDSS — BLERP: BLE Re-Pairing Attacks and Defenses](https://www.ndss-symposium.org/ndss-paper/blerp-ble-re-pairing-attacks-and-defenses/)

**论文 PDF：** [2026-f121-paper.pdf](https://www.ndss-symposium.org/wp-content/uploads/2026-f121-paper.pdf)

**Slides PDF：** [f0121-sacchetti-slides.pdf](https://www.ndss-symposium.org/wp-content/uploads/f0121-sacchetti-slides.pdf)

**Black Hat Asia 2026 研究团队条目：** [EURECOM — Exploiting BLE re-pairing with the BLERP attacks](https://www.eurecom.fr/en/publication/8697?slug=exploiting-ble-re-pairing-with-the-blerp-attacks)

研究针对 BLE re-pairing：标准允许已经配对的设备重新协商并覆盖长期配对密钥，但研究发现该机制存在多项设计层问题，包括未认证 re-pairing 和安全级别 downgrade。攻击可以实现 Central/Peripheral impersonation 以及单/双通道 MitM。

更重要的是，它不是只停留在协议推导。作者实现了 BLERP toolkit，使用低成本 **nRF52** 硬件以及 **Mynewt、NimBLE、Scapy** 等开源软件执行 over-the-air pairing/re-pairing 测试和端到端 MitM，并在 22 个目标设备上做了评估。

可以把研究链路概括为：

`BLE pairing/session establishment → re-pairing trust boundary → LTK/PK 被覆盖或降级 → nRF52 OTA 攻击工具 → impersonation / MitM → vendor/standard mitigation`

这类材料非常适合作为 wireless hack 的学习模板：先读标准和状态机，再找 trust boundary，然后用低成本 RF/协议硬件构造实际攻击，最后回到协议修复。

### 本期最值得精读的会议 / 活动研究

**BLERP。** 原因不是漏洞影响最大，而是它的资料完整度最高：具体研究页、论文、slides、演讲、低成本硬件和可复现工具链都能串起来。

## 五、本期最值得精读的 RF 原理文章

### PySDR：End-to-End Example with RDS

[PySDR 的 RDS End-to-End Example](https://pysdr.org/content/rds.html) 很适合作为前几期 IQ Sampling、Link Budget、Synchronization 之后的“整链路练习”。它使用真实 FM 广播中的 Radio Data System（RDS）作为对象，把多个独立 DSP 概念真正串在一起：

`IQ acquisition → FM demod → frequency shift → filtering → decimation/resampling → symbol timing → fine frequency sync → BPSK demod → bit/byte parsing`

它的价值在于解释一个常见误区：学完 FFT、滤波、Costas loop，并不代表已经会做 SDR receiver。真实 receiver 的难点往往在各 block 的顺序、采样率转换、频偏残差、同步状态和 protocol framing 之间的耦合。

**建议实践：** 直接使用章节提供的 IQ 数据，不修改算法，先画出每一级输出；然后故意改变 frequency offset、filter bandwidth、resampling ratio 或 timing 参数，观察错误如何从前一级传播到最终 bit decode。

### 本期最值得精读的 RF 原理文章

**PySDR — End-to-End Example with RDS。** 它适合把之前分散学习的 IQ、filter、resample、timing 和 carrier synchronization 第一次真正组合成一个可运行接收机。
