Maia SDR 的结构非常清晰：`maia-hdl` 负责 FPGA 数据面，`maia-httpd` 在 Zynq ARM 上运行异步 Rust Web 服务，`maia-kmod` 管理 FPGA/CPU 之间的 RAM buffer，`maia-wasm` 通过 WebAssembly/WebGL2 提供瀑布图 UI。citeturn112740search1

## 四、本期最值得精读的 RF 原理文章

### PySDR：Synchronization

本期从长期高价值来源 PySDR 中选择 **Synchronization**。PySDR 是一套免费在线 SDR/DSP 教材，覆盖 FFT、滤波、数字调制、SDR 收发、链路预算、IQ/SigMF 和同步等系统内容；它已经在此前简报中多次提供高价值原理材料。citeturn819025search11

Synchronization 章节把时间与频率同步放进同一接收链路中，具体覆盖 symbol timing、coarse frequency synchronization、fine frequency synchronization 和 Costas Loop。citeturn819025search2

建议建立这样的接收机模型：

1. Tx/Rx 本振不可能完全一致，因此会产生 carrier frequency offset；
2. 接收采样点通常不会自然落在最佳 symbol instant，需要 timing recovery；
3. coarse frequency estimation 先处理较大的 CFO；
4. fine carrier loop 再持续跟踪残余频偏和相位；
5. fine frequency synchronization 往往在 symbol timing 已基本建立后效果更好，所以多个同步模块之间存在顺序和耦合。

PySDR 给出的一个很直观例子是：Pluto 的本振最大误差规格如果按 25 ppm 计算，在 2.4 GHz 上可对应约 ±60 kHz 的频偏。也就是说，“几十 ppm”看起来很小，但映射到 GHz 载波后，对复基带解调已经是明显的 CFO。citeturn819025search2

**适用方向：** BPSK/QPSK 等数字调制、Pluto/HackRF/RTL-SDR IQ 数据、协议解调前端、Costas loop、Mueller & Muller timing recovery。

**建议实践：** 对一段自有或公开 IQ 数据人为加入已知 CFO 与 sampling offset，依次观察粗频偏估计、timing recovery 和 Costas loop 前后的频谱和星座变化。

### 本期最值得精读的 RF 原理文章

**PySDR 的 Synchronization。** 它适合作为接收机同步链路的总入口，并且能与此前已经收录的 IQ Sampling、Link Budgets 组成连续的系统学习路径。
