## 一、软件为主的 SDR / wireless hack 动向与新项目

### AetherSDR v26.9.2
具体入口：https://github.com/aethersdr/AetherSDR/releases/tag/v26.9.2

AetherSDR 当前版本已到 26.9.2。这一轮最值得关注的不是单一 UI 功能，而是 radio backend 明显继续扩张：新增 experimental RTL-SDR USB receive path、experimental ANAN-G2/openHPSDR Protocol 2 receive path，以及最多四路 TCI DAX IQ subscription 支持多 band skimming。RTL-SDR 路径目前提供单 slice/panadapter 与基础 AM/FM/SSB/CW demod；ANAN-G2 当前也以 receive-only 为主。

从架构上看，AetherSDR 正从“FlexRadio client”逐步演变成多 radio frontend 的统一 workstation：不同硬件 backend 共享 spectrum/waterfall、slice、demod 和 station-control 层，但 capability 仍按真实硬件能力 gating，而不是假设所有 radio 具有同一能力。

**本期最值得试用的软件项目：AetherSDR v26.9.2。** 推荐重点观察 RTL-SDR backend 如何把 USB IQ source 接入已有 panadapter/demod 架构，以及多路 DAX IQ subscription 如何避免重复数据路径。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### Universal High-Bandwidth SDR Transceiver for RFSoC4x2 and GNU Radio
具体议题：https://events.gnuradio.org/event/28/contributions/870/
开源代码：https://github.com/strath-sdr/rfsoc_qsfp_offload

GRCon26 的该项目公开了具体代码仓库。其前代架构已经实现超过 70 Gbit/s 的持续 RF sample host offload，可让 GPU 侧观察最高约 2.4576 GHz instantaneous bandwidth；当前版本继续向双向 QSFP SDR transceiver 演进。

新版本的关键工程变化包括：用 PYNQ.remote/gRPC 取代原先 XML-RPC 控制路径，让 host Python/GNU Radio 直接完成 overlay load、MMIO、RFDC 参数控制；通过运行时 DUC/DDC 与 clock wizard 支持更灵活的 sample-rate/bandwidth；并增加 PL DDR burst-capture path，在 host 无法持续接住 100GbE 全速数据时保留短时高带宽采集能力。

这是一条很典型的现代高带宽 SDR 分层：RF ADC/DAC → RFSoC DUC/DDC/stream routing → QSFP 100GbE continuous path 或 PL DDR burst path → host/GPU GNU Radio processing。

**本期最值得关注的软硬件一体项目：RFSoC4x2 + GNU Radio 高带宽 SDR。** 它特别适合研究 FPGA/host 控制面、高速 streaming、burst capture 与 GPU DSP 的边界。

## 三、RF / Wireless 最新动态与新闻

### CVE-2026-5706：Silicon Labs Bluetooth Mesh extended advertisement 内存破坏
参考：https://www.cve.org/CVERecord?id=CVE-2026-5706

Silicon Labs Bluetooth Mesh SDK 6.1.4 及更早版本存在 extended advertisement 处理问题：恶意构造的 extended advertisement 可触发 out-of-bounds write，导致 stack corruption 并可能达到 remote code execution。攻击消息需要来自已经加入 mesh 的设备，且影响重点是支持 extended advertisements 的 provisioner。

这类问题值得从 RF attack surface 看，而不仅是记一个 CVE：BLE extended advertising 允许比 legacy advertising 更大的 payload，最终仍会进入 embedded mesh parser；一旦 length/fragment 处理和固定 buffer 边界不一致，无线帧即可直接转化为 memory-corruption primitive。公开 CVE 数据给出的 CVSS 4.0 base score 为 8.9。

## 四、会议 / 活动高质量研究

### GRCon26：Detecting Falsified UAV Telemetry — An SDR Approach to Remote ID Spoofing Detection
具体会议入口：https://events.gnuradio.org/event/28/contributions/887/

这是一个很符合本栏目定位的研究：FAA Remote ID 等系统要求无人机广播位置、速度与控制站信息，但 Remote ID 本身是 RF broadcast，接收者不能仅因为“packet 格式正确”就认为其中的物理位置是真实的。

研究思路是建立一条独立 RF 物理验证链：接收 Remote ID → 取得 packet 声称的位置/速度 → 用 SDR 实时捕获实际 RF → 提取 RSSI、Doppler shift、AoA 等与物理传播相关的信息 → 判断广播 telemetry 与真实发射源物理特征是否一致。

其价值在于把“协议层身份声明”与“物理层测量”进行交叉验证。攻击者可以伪造 packet field，但无法任意控制接收端看到的传播损耗、运动产生的 Doppler、多个接收通道测得的 AoA 等所有物理量。这种思路可以推广到 ADS-B、AIS、无线 beacon 与其他未强认证的广播系统。

## 五、本期最值得精读的 RF 原理文章

### PySDR：TDOA
具体文章：https://pysdr.org/content/tdoa

TDOA（Time Difference of Arrival）通过多个空间分离 receiver 对同一 RF emitter 的到达时间差估计发射源位置。核心不是测“绝对传播时间”，而是测 receiver 之间的相对 delay：每一对接收站的 delay 对应一个 range difference，进而形成双曲线/双曲面定位约束，多组约束交汇得到 emitter 位置。

对 SDR 系统来说，真正困难的部分通常有三层：第一，多个 receiver 必须有足够好的时间/频率同步；第二，需要通过 cross-correlation/GCC 等方法从 noisy IQ 中估计非常小的 sample delay；第三，多个 TDOA measurement 并非天然独立，例如都使用同一个 reference receiver 时，measurement noise 会产生相关性，定位算法应正确处理 covariance。

它和前几期的 distributed/coherent SDR、RF geolocation、Remote ID spoofing detection 正好连接起来：单个 SDR 只能告诉你“我收到了这个信号”；多站 TDOA 则进一步回答“这个 RF emitter 在物理空间哪里”。

建议实验：用两路或三路同步 IQ，先对同一录制信号人工加入整数/小数 sample delay，比较 time-domain cross correlation、frequency-domain correlation 和不同 SNR 下的 delay error；随后再把 delay 转成 range difference，观察 baseline geometry 对定位误差的放大。

**本期最值得精读的 RF 原理文章：PySDR — TDOA。**
