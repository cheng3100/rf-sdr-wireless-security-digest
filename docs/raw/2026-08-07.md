## 一、软件为主的 SDR / wireless hack 动向与新项目

### AetherSDR v26.7.4.1

AetherSDR 在 **2026 年 7 月 27 日**发布 v26.7.4.1，修复了前一版本引入的 TCI rig-control 回归，使 WSJT-X 和外部控制面重新可用。近期版本还持续加入本地 D-STAR、MCP Server、3D stacked-trace FFT、噪声抑制和演示模式等功能。citeturn760364search9

它值得关注的重点，不只是某一个解调器，而是桌面 SDR 客户端正在整合更多上层能力：

- 实时频谱和多 VFO；

- 外部台站与软件控制；

**适用硬件与方向：** 业余无线电收发机、网络 SDR、数字语音、WSJT-X 联动和需要自动化控制的接收环境。

### SDR++ Nightly 1.3.0

SDR++ 继续采用 rolling/nightly 发布模式，当前 nightly 标记为 1.3.0，并提供 Windows、Linux、macOS 和 Android 等多平台构建。项目本身强调多 VFO、SIMD 加速 DSP、模块化 source/sink/decoder，以及 SoapySDR 与多种原生硬件后端。citeturn736103search0turn736103search3

它适合两个用途：

1. 作为轻量、跨平台的日常频谱观察工具；

尤其值得关注 `source_modules`、`decoder_modules` 和 `sink_modules` 的边界：它们展示了硬件输入、DSP 数据流与最终输出如何被拆分成独立模块。

**适用硬件：** RTL-SDR、HackRF、Airspy、bladeRF、LimeSDR、SDRplay 以及其他 SoapySDR 设备。

### GNU Radio 4：Web 监控与 CyberEther 互操作

GNU Radio 2026 年 GSoC 项目中，一项工作为 GNU Radio 4 开发基于 Web 的运行中 flowgraph 监控 OOT 模块，另一项探索 CyberEther 与 GNU Radio 的图形化互操作；此外还有 hardware-in-the-loop CI 项目。citeturn657001search10

这几个方向共同指向一个趋势：

```text
传统本地 GNU Radio flowgraph
             ↓
可远程观察、可自动测试、可跨工具编排
             ↓
长期运行的 SDR 实验和服务平台
```

对复杂 SDR 系统而言，真正困难的部分往往不只是 DSP block 本身，还包括：

- 当前数据率与 buffer 状态；
- 哪个 block 出现 backpressure；
- 远程修改参数；
- flowgraph 的部署和生命周期；
- 真硬件参与下的持续集成。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### PortaPack Mayhem Nightly 2026-07-26

PortaPack Mayhem 在 7 月继续保持较高频率的 nightly 构建，最近公开构建为 **2026 年 7 月 26 日**。它把 HackRF、显示屏、按键、存储和设备端 RF 应用组合成便携平台。citeturn159349search1

对软硬件系统学习而言，可以重点分析：

```text
HackRF RF/CPLD/MCU
        ↓
PortaPack 硬件接口
        ↓
Mayhem 设备端 DSP
        ↓
UI、存储与协议应用
```

这种设备端架构和 PC SDR 客户端明显不同：

- 内存和 CPU 更受限；
- UI 与 DSP 争用资源；
- 必须考虑实时性和存储吞吐；
- 用户期待开机即用，而不是现场编译或调流图。

**适用频段与实践：** HackRF 覆盖范围内的频谱观察、协议接收、便携式现场分析，以及自有设备和授权环境中的 RF 研究。

### Maia SDR v0.12.0

Maia SDR v0.12.0 更新了 Rust 2024 生态和多个内部组件。项目继续提供基于 ADALM-Pluto 的 FPGA 实时瀑布图、浏览器界面，以及最高 61.44 Msps 的 SigMF IQ 录制。citeturn159349search0turn760364search4

它的系统结构非常适合有驱动和芯片背景的人阅读：

```text
AD936x RFIC
    ↓
FPGA DSP / FFT / buffering
    ↓
Linux kernel module
    ↓
Rust embedded service
    ↓
WebAssembly / browser UI
```

Maia SDR 的核心价值，是避免把全部高采样率 IQ 数据持续搬到 PC 后再做处理。频谱计算和部分数据处理下沉到 FPGA，主机只获取必要的结果或选择性 IQ 数据。

**适用方向：** PlutoSDR、FPGA SDR、远程频谱监控、SigMF 数据采集，以及设备端 DSP。

### TrojPix：数字视频线缆的高速电磁隐蔽信道

TrojPix 通过人眼难以察觉的像素调制，控制数字视频线缆产生的电磁辐射。研究在多个商用显示器品牌和数字视频线缆上进行了测试，报告最高 **8.1 Mbps**、最远 **208 米**的实验结果。citeturn870875search4

它与传统 wireless hack 的差异在于，攻击对象不是一个设计好的无线协议，而是设备的非预期电磁发射：

```text
屏幕像素变化
      ↓
数字视频数据模式变化
      ↓
视频线缆电流与边沿变化
      ↓
可观测的电磁辐射
      ↓
SDR 捕获、同步与解码
```

从防御和研究角度，值得关注的技术点包括：

- 哪些数据模式能形成稳定频谱特征；
- 如何建立像素与 RF sample 的映射；
- 接收端如何完成帧同步；
- 环境噪声和不同线缆如何影响信道；
- 如何检测异常显示模式或电磁泄漏。

## 四、本期最值得精读的 RF 原理文章

### PySDR：Link Budgets

PySDR 的链路预算章节从系统角度解释发射功率、收发天线增益、路径损耗、噪声功率、带宽和 SNR 如何组合，并使用 ADS-B 给出完整示例。该章节也有中文版本。citeturn733681search0turn733681search1

链路预算的基本思想是：

```text
发射功率
 + 发射天线增益
 - 传播损耗
 - 线缆及其他损耗
 + 接收天线增益
 = 接收信号功率
```

然后再计算接收机噪声：

```text
热噪声密度
 + 接收带宽
 + 接收机噪声系数
 = 接收噪声功率
```

最终：

```text
接收信号功率 - 接收噪声功率 = SNR
```

### 为什么它对 SDR 实践重要

使用 SDR 时，经常出现这种情况：

- 瀑布图中似乎能看到信号，但无法解调；
- 更换天线后的效果远大于修改 DSP 参数；
- 放大增益后信号和噪声同时上升；
- 采样带宽扩大后，噪声底明显提高；
- 同一设备在 433 MHz 表现良好，在 2.4 GHz 距离明显变短；
- 加 LNA 后效果反而变差，因为前端被强信号压缩。

这些现象都不能只用“解调算法是否正确”解释。必须把以下因素放到同一系统中：

- 发射功率；
- 天线方向性和增益；
- 自由空间及非自由空间路径损耗；
- 馈线、连接器和匹配损耗；
- 接收带宽；
- 噪声系数；
- 前端动态范围；
- 解调器所需最低 SNR。

### 阅读时建议重点理解

1. **dB、dBm 和 dBW 的区别**  
   dB 表示比值；dBm 和 dBW 表示绝对功率。

2. **频率为什么影响路径损耗**  
   在相同距离条件下，频率越高，自由空间路径损耗越大。

3. **带宽为什么影响噪声底**  
   接收带宽越宽，积分进来的热噪声越多。

4. **天线增益不是凭空放大能量**  
   高增益天线通过缩小方向范围集中能量。

5. **能看到信号不等于能够解调**  
   解调器仍要求一定的 SNR、同步质量和前端线性度。

### 本期最值得精读的 RF 原理文章

**PySDR 的 Link Budgets。**

它能把天线、传播、射频前端、噪声和解调所需 SNR 连接起来，帮助学习视角从“软件里看频谱”上升到完整无线链路的系统思维。
