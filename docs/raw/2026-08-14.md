# RF / SDR / Wireless 技术情报 · 2026-08-14

## 一、软件为主的 SDR / wireless 研究动向与新项目

### SatDump 2.0 Alpha
SatDump 在 2026 年 6 月开始发布 2.0.0 Alpha，继续把卫星信号的 SDR 采集、实时解调、纠错、协议解析、图像/遥测恢复和离线处理整合到一套工具链中。它支持直接从 SDR 设备采集，也支持对已有 IQ/baseband 文件运行 pipeline。

为什么值得关注：这是“从 IQ 到最终业务数据”这一整条链路较完整的开源样本。相比单独搭 GNU Radio 流图，它更适合观察产品化 SDR 软件如何组织 source、demod、FEC、framing、协议 parser 和结果展示。

适用方向：NOAA/MetOp/业余卫星等卫星接收，常见 VHF/UHF/L/S 波段；也适合学习 CCSDS、DVB-S2、AX.25 等协议栈与 SDR 数据通路的结合。

来源：[SatDump 2.0 Alpha](https://www.satdump.org/tags/release/) · [SatDump GitHub](https://github.com/SatDump/SatDump)

### SDR++ Nightly 1.3.0
SDR++ 当前 nightly 仍处于 1.3.0 系列，持续提供 Windows、Linux、macOS 与 Android 构建，并保持多 VFO、模块化 source/sink/decoder、SIMD DSP 和多种 SDR 后端支持。

为什么值得关注：它很适合作为“通用 SDR 客户端”代码阅读对象，尤其是 source module 与 DSP/decoder 的边界，有助于理解用户态如何抽象不同 SDR 硬件、如何组织实时 stream 与 UI。

适用硬件：RTL-SDR、HackRF、Airspy、LimeSDR、SDRplay 以及 SoapySDR 兼容设备。

来源：[SDR++ Releases](https://github.com/AlexandreRouma/SDRPlusPlus/releases)

### gr-satellites 主线聚焦 GNU Radio 3.10
gr-satellites 当前 v5.x 主线面向 GNU Radio 3.10，项目已经冻结 GNU Radio 3.8/3.9 分支。它覆盖 AX.25、GOMspace、CCSDS、AO-40 等多种业余卫星与空间通信协议。

为什么值得关注：它展示了成熟 OOT module 如何把 GNU Radio block 组织成可复用协议解码库，而不是只做单一 flowgraph。

来源：[gr-satellites](https://github.com/daniestevez/gr-satellites)

### 本期最值得试用的软件项目
**SatDump 2.0 Alpha。** 它对“从 RF 到协议数据”的覆盖最完整，尤其适合把 SDR、DSP、协议和工程化软件架构连起来学习。

## 二、软硬件结合的 SDR / wireless 开源项目动向

### PortaRF
PortaRF 是 2026 年出现的开源单板便携 SDR，尝试把 HackRF One 与 PortaPack H4M 的能力整合到一块 PCB 上，并保持约 1 MHz–6 GHz 的收发范围。相比 HackRF + PortaPack 的堆叠组合，它把 MCU、CPLD、RF 前端、显示和电源进一步收敛成单机平台。

为什么值得关注：这是典型的“成熟开源 SDR 生态二次整合”案例，适合研究硬件复用、接口收敛、便携化和设备端应用之间的取舍。

来源：[PortaRF 介绍](https://www.cnx-software.com/2026/05/14/portarf-single-board-sdr-mixes-hackrf-one-and-portapack-h4m-hardware-adds-ai-voice-control/)

### PortaPack Mayhem 2.4.0 与持续 nightly
Mayhem 稳定版仍为 2.4.0，社区同时保持大量 nightly 构建。它把 HackRF 变成无需 PC 即可运行多类 RF 应用的便携平台，重点包括设备端 DSP、协议工具、录制、UI 与 SD 卡应用管理。

为什么值得关注：对比 PC 端 SDR，Mayhem 更能暴露受限 CPU/内存条件下的实时性问题，以及 UI、DSP、存储和 RF 控制之间的资源竞争。

来源：[Mayhem Firmware](https://github.com/portapack-mayhem/mayhem-firmware)

### Maia SDR
Maia SDR 仍是非常值得跟踪的 FPGA SDR 项目：以 ADALM-Pluto/Pluto+ 为主要平台，把高带宽 FFT/频谱处理放到 FPGA，ARM 侧运行 Rust 服务，浏览器通过 WebSocket/WebGL 展示瀑布图，并支持 SigMF IQ 录制。

为什么值得关注：其架构非常清晰地展示了 RFIC、FPGA、Linux kernel module、嵌入式服务与浏览器 UI 的分层关系。

来源：[Maia SDR](https://maia-sdr.org/) · [GitHub](https://github.com/maia-sdr/maia-sdr)

### 本期最值得关注的软硬件一体项目
**PortaRF。** 它把 HackRF + PortaPack 的成熟生态进一步压缩成单板平台，最适合观察一个开源 SDR 如何从“开发板组合”向“完整设备”演进。

GRCon26 将于 9 月 21–24 日在 Raleigh 举办，由 NC State/AERPAW 承办。议题覆盖 SDR 开发、无线系统、AI/ML、5G/6G、硬件集成、教育与实验平台。

为什么值得关注：GNU Radio 社区正在明显从“桌面 flowgraph 工具”扩展到远程实验平台、真实无线试验床和复杂系统工程。

## 四、本期最值得精读的 RF 原理文章

### PySDR：IQ Sampling
PySDR 的 IQ Sampling 章节仍然是非常适合反复阅读的基础材料。它从复数、正负频率、混频和采样的角度解释：为什么 SDR 不是只输出一个实数 ADC 流，而是通常输出 I/Q 两路构成的复基带信号。

来源：[PySDR — IQ Sampling](https://pysdr.org/content/sampling.html)

### 为什么这一主题值得重新精读
很多 SDR 初学问题都可以追溯到 IQ 概念没有完全建立：为什么复采样带宽与采样率对应、为什么下变频后存在负频率、为什么频偏表现为 IQ 平面持续旋转、为什么 IQ imbalance 会产生镜像，以及为什么零中频接收机会出现 DC offset/LO leakage。

建议配合一个真实 IQ 文件做三个安全的离线实验：对 IQ 做 FFT 观察正负频率；人为加入频偏观察频谱平移和星座旋转；人为修改 I/Q 幅度或相位观察镜像 spur。

### 本期最值得精读的 RF 原理文章
**PySDR 的 IQ Sampling。** 这是理解现代 SDR 数据表示的地基，长期价值远高于某个具体协议或工具版本。
