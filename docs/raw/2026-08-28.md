## 一、软件为主的 SDR / wireless hack 动向与新项目

### AetherSDR v26.8.4：从“FlexRadio 客户端”继续扩展成多无线电工作台

AetherSDR 在 2026-08-23 发布 v26.8.4。这个版本的重点不是单一 UI 修补，而是继续扩展 Icom 与 Hermes-Lite 2 等不同 radio backend 的真实能力建模：IC-705、IC-7300MK2、IC-9700 使用更严格的 capability profile；增加/完善 CI-V CW text keying、真实 IF width/PBT 与 TX cut readback、FM repeater tone/duplex/XFC，以及 IC-9700 的有限恢复机制；Hermes-Lite 2 则加强 client-timed CW。PSK Reporter map、NR2、MIDI/TCI 与 workspace 等也有改进。

项目入口：https://github.com/aethersdr/AetherSDR/releases/tag/v26.8.4

为什么值得关注：它展示了一个现代 SDR/ham-radio workstation 如何避免“所有 radio 都假设同一套寄存器/能力”的粗糙抽象，而是把协议、model capability、DSP/UI 和网络控制分层。对于阅读复杂 SDR 客户端代码，比只看一个 decoder 更能看到真实工程问题。

适用硬件/协议：FlexRadio FLEX-6000/8000/Aurora、部分 Icom 网络/CI-V radio、Hermes-Lite 2；重点涉及 SmartSDR、CI-V、网络 SDR 控制、CW/FM/SSB 等业余无线电工作流。

与 SDR 实践的关系：可重点看“频谱/瀑布图更新速率、网络 transport、radio authoritative state、DSP control 与 UI 状态同步”之间的耦合，这类问题和远程 SDR、嵌入式 SDR 控制面非常接近。

### GNU Radio 4：官方仓库组织进入正式化阶段

GNU Radio 官方在 2026-08-16 宣布 GNU Radio 4 的 GitHub 组织方式正式重构：核心 runtime、可复用 DSP library、标准 blocks、control plane、studio 等逐步拆成职责明确的仓库，并通过 super-repo/builder 组合。这不是 GNU Radio 4 正式 release，但意味着 GR4 从原型/过渡仓库进一步走向长期维护结构。

官方说明：https://www.gnuradio.org/news/
核心仓库：https://github.com/gnuradio/gnuradio4-core
DSP library：https://github.com/gnuradio/gnuradio4-library
标准 blocks：https://github.com/gnuradio/gnuradio4-blocks

为什么值得关注：GR4 的变化不只是 C++23 或 API 更新，而是 runtime / graph / block SDK / DSP algorithm / application 层次被更清晰地拆开。对以后写 OOT module、做硬件接入、远程控制和 HIL 测试都更重要。

适用方向：通用 SDR flowgraph、DSP pipeline、OOT modules、Soapy/UHD 等硬件接入、实验室自动化。

### 本期最值得试用的软件项目

**AetherSDR v26.8.4。** 它已经是可直接运行的真实软件，并且本期更新非常适合观察“多 radio backend + 网络协议 + DSP/UI 状态机”这种实际 SDR 工程结构；GNU Radio 4 更适合继续作为中长期框架演进跟踪对象。

## 二、软硬件结合的 SDR / wireless hack 开源项目动向

### PortaPack H4M Pro：硬件文件正式开源并合入 Mayhem

OpenSourceSDRLab 在 Mayhem 仓库 PR #3298 中提交 H4M Pro 的 PCB、Gerber 和 schematic 文件；该 PR 已合并。提交说明明确指出 H4M Pro 的 schematic 与 H4M 基本相同，主要差别之一是 18650 电池座，同时加入了完整制造相关文件。

具体 PR：https://github.com/portapack-mayhem/mayhem-firmware/pull/3298

为什么值得关注：此前 H4M Pro 更多是“可以买到并运行 Mayhem 的硬件”，这次硬件制造文件进入主流 Mayhem 生态后，它更接近可审计、可改板、可复刻的软硬件一体平台。对 RF 实验者而言，价值不只在便携性，而是可以把 RF board、MCU/CPLD、显示/存储、电源和 Mayhem firmware 放到一个完整系统里分析。

适用频段/硬件：核心仍基于 HackRF/PortaPack 生态，覆盖 HackRF 的宽带 RF 范围，适合 Sub-GHz、VHF/UHF、ISM、航空/海事、TETRA 等多类接收/分析实验。

与 wireless hack 实践的关系：对协议捕获、现场频谱扫描、独立设备端解调/分析尤其有价值；同时因为 PCB/Gerber 已公开，可以进一步研究 RF layout、电源噪声、屏蔽、扩展接口和便携化设计对接收性能的影响。

### 本期最值得关注的软硬件一体项目

**H4M Pro 硬件开源进入 Mayhem 主仓。** 这是比“发布一个新外壳/新 SKU”更有长期价值的变化，因为它真正增加了可复现、可审计和可二次设计能力。

## 三、RF / Wireless 最新动态与新闻

### BlueZ：A2DP stream endpoint 栈溢出可导致 root 上下文代码执行

Zero Day Initiative 在 2026-08-24 公布 ZDI-26-589 / CVE-2026-19774。漏洞位于 BlueZ 对 A2DP stream endpoint 的处理：对用户可控长度缺少充分校验，在复制到固定长度栈 buffer 时造成溢出。攻击者需要先让恶意 Bluetooth 设备与目标完成 pairing，但成功后可能在 bluetoothd/root 上下文执行代码。BlueZ 已提供修复。

官方 ZDI：https://www.zerodayinitiative.com/advisories/ZDI-26-589/

为什么值得关注：这是很典型的“无线协议输入最终进入高权限系统 daemon”的攻击链。对 wireless hack 而言，RF 链路只是入口，真正的漏洞位于 profile parser 和内存安全边界。

适用协议/硬件：Bluetooth Classic / A2DP，Linux BlueZ；攻击者需要 Bluetooth radio 和可配对设备能力。

### BlueZ：EIR discovery 路径又出现一个无需 pairing 的栈溢出

CVE-2026-80186 在 2026-08-25 公开，描述为 BlueZ 在设备 discovery 处理 Extended Inquiry Response（EIR）时的 stack-based buffer overflow。攻击者处于 Bluetooth 无线范围内即可发送精心构造的 EIR packet；公开描述指出可导致 bluetoothd 崩溃，并可能达到代码执行。与前一个 A2DP 漏洞相比，它更值得注意的一点是攻击面落在 discovery 阶段，不要求先建立正常 profile session。

参考：https://security.snyk.io/vuln/SNYK-DEBIAN11-BLUEZ-19268263

为什么值得关注：Bluetooth discovery 往往被认为是“只是在扫设备”，但实际上 inquiry/EIR 元数据同样是复杂的外部输入。对于 Linux wireless stack 安全分析，应该把 HCI event、EIR/AD parser、profile parser 一起纳入 attack surface。

### 本期最值得关注的 RF / Wireless 动态

**BlueZ 在一周内连续暴露两条 Bluetooth 栈内存安全攻击面。** 一个位于已配对后的 A2DP stream endpoint，另一个位于 discovery/EIR 阶段；两者放在一起看，比单独看 CVE 更能说明无线协议 parser 与高权限 daemon 之间的安全边界仍然值得系统 fuzzing 和 OTA 测试。

## 四、会议 / 活动高质量研究

### USENIX Security ’26：Injected and Leaked — 主动 RF 注入诱导电磁侧信道泄漏

具体 session：https://www.usenix.org/conference/usenixsecurity26/presentation/yan-haoran
论文 PDF：https://www.usenix.org/system/files/usenixsecurity26-yan-haoran.pdf

这项研究把传统上分开的两个问题连接起来：EM injection 通常用于影响系统完整性，EM side-channel leakage 通常用于窃取信息；作者研究的是能否通过主动注入 RF，让本来难以观测的低频秘密被硬件非线性“搬移”到更容易远距离接收的电磁频段。

核心机制是：放大器、ADC、电源转换器等非线性器件会把低频 secret signal 与外部注入的 RF carrier 混频/调制，形成新的可观测频谱分量。攻击者通过调节注入频率与幅度，主动塑造泄漏的频谱与信息量。

作者设计 InjectEave，并展示：使用可获得的 RF equipment，可对有线和无线耳机正在播放的音频进行远距离窃听，实验距离达到约 30 m，并包含穿墙场景；还分析了智能家居功耗、模拟传感器输入等低频秘密的 injection-induced leakage，并给出固定电话闭环窃听/操纵案例。

研究链路：

RF injection → hardware nonlinearity → low-frequency secret 被上变频/调制到泄漏载波 → RF receiver 捕获 → signal processing / recovery → eavesdropping 或 closed-loop manipulation。

适用硬件/频段：论文涉及可获得的 RF 注入/接收设备，目标则包含耳机、放大器、ADC、电源转换和模拟接口；具体频率与实验参数应以论文实验章节为准，而不是把它简单归到某个无线协议频段。

为什么值得 wireless hack / SDR 精读：这是非常典型的“不是攻击一个标准无线协议，而是利用真实硬件的模拟非理想性建立隐蔽 RF 信道”。SDR 在这里承担的是频谱观察、信号捕获、频率扫描和后续恢复，而漏洞根因在 mixed-signal hardware。

## 五、本期最值得精读的 RF 原理文章

### PySDR：Pulse Shaping

文章：https://pysdr.org/content/pulse_shaping

这一章系统解释 pulse shaping、ISI、matched filter、raised-cosine / root-raised-cosine（RC/RRC）、roll-off factor、eye diagram，并进一步联系 OQPSK 与 MSK。它非常适合作为从“会调制”进入“理解真实波形为什么长这样”的关键章节。

核心工程关系可以概括为：

离散 symbol → 上采样 → Tx RRC pulse shaping → channel/noise → Rx matched RRC → timing recovery → symbol sampling。

为什么不能直接发方波 symbol：矩形脉冲具有很宽的频谱，占用大量带宽；但随便低通又会让相邻 symbol 在最佳采样点互相干扰。Nyquist pulse-shaping 的关键是让其他 symbol 的 pulse 在目标 symbol 的采样时刻恰好过零，从而允许时域波形重叠但不产生理想采样点上的 ISI。

为什么 Tx/Rx 各放一个 RRC：两个 RRC 级联后得到整体 RC 响应；接收端 matched filter 同时帮助在 AWGN 下最大化采样点 SNR。roll-off β 则直接体现频谱占用与时域脉冲长度之间的折中，常见无线系统会选择大约 0.2–0.5 的范围。

与 SDR 捕获/解调的关系：当你抓到 PSK/QAM IQ 后，如果 matched filter、samples-per-symbol、symbol timing 或 roll-off 假设不正确，星座会扩散、eye 会闭合，即使载波频偏已经校正也可能无法稳定判决。因此 pulse shaping 是理解 symbol timing recovery 的前置知识，而不是仅属于发射机。

推荐实验：用 Python 或 GNU Radio 生成 BPSK/QPSK，固定 SNR 后依次改变 β、Rx matched-filter 参数与 sampling instant；同时观察 PSD、eye diagram 和 constellation。这样可以直接看到“频谱更紧”和“timing margin 更小”之间的工程权衡。

### 本期最值得精读的 RF 原理文章

**PySDR — Pulse Shaping。** 它能把滤波、带宽、ISI、matched filter、symbol timing 和 eye diagram 串成一条连续理解链，适合作为此前 IQ、同步和完整 receiver 学习之后的进一步深化。
